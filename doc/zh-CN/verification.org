* 有界 Release 微基准

命令：=cargo bench --locked -p zust-log --bench logging -- --run=。
每组先预热 2,000 次，再采样 50,000 次单生产者调用。启用日志的两组使用相同后端
大小轮转缓冲文件 sink 配置，只输出消息和换行，关闭周期/级别刷新，测量期间不轮转。
最终刷新后比较两组完整输出一致；成功时删除本次基准独占的临时文件。

| 场景 | 每秒调用数 | P50 ns | P99 ns |
|------+------------+--------+--------|
| 原生后端启用 | 6,229,905 | 135 | 245 |
| zust 启用 | 3,421,618 | 265 | 323 |
| 原生后端关闭 | 31,712,306 | 14 | 16 |
| zust 关闭 | 29,997,510 | 16 | 22 |

这是单次本机结果，不是统计性能保证；包含时钟采样和样本收集开销。启用时的差值
包含元数据、通道路由、兼容格式化及生命周期协调。门面重导出自身不增加运行时工作。
未测默认完整文本、important JSONL、异步吞吐、饱和延迟、fsync 或持续磁盘性能。
默认正确性测试跳过性能测量。

* 过载策略验证 — 2026-10-21

本条覆盖此前“队列满则阻塞”的当前契约，保留上方历史结果。
环境为 Rust 1.97.1、锁定依赖、Linux x86_64。

- Debug、Release 的 =cargo test --locked -p zust-log --lib --tests= 均通过：
  五个单元测试、三个配置测试、三个 runtime harness 测试（18 个操作子场景及静态级别场景）。
- 暂停容量一后端，验证公共 important/warn/error 满时返回、仅丢新、关闭后公共统计
  保留三条丢弃、显式 flush 可靠，以及已接收 warn 在 worker 按级别刷新。
  可控时钟覆盖五秒限频及最终增量。
- 并发关闭场景改为校验已输出接收数 + 丢弃数 = 实际求值提交数，排除合成汇总行。
  原有真实异步轮转故障继续归类输出错误。
- 重命名门面/组件消费者及新共享统计接口在 Debug、Release 均通过；两种配置的
  Clippy（警告视为错误）通过；门面单元选择及门面/组件两个可执行文档示例通过。
- 未执行完整交付构建、下游应用运行、sanitizer、长时间压测或性能对比；原生基准
  仍为同步基准。
